# Friday firmware — ESP32 + ST7789 + MAX9814

Проект ESP-IDF **v5.5.2** для обычного ESP32 / ESP-WROOM-32 (NodeMCU-32S),
не для ESP32-S3/C3. После запуска показывает **WIFI CONNECTING**, подключается к Wi-Fi,
затем примерно 3 секунды калибрует фон (**QUIET PLEASE** — соблюдать обычную тишину).
После успешных проверок экран пуст. По слову «Пятница» плата показывает **LISTENING** и передаёт звук на Mac до полутора секунд тишины.
При удержании сенсорной кнопки на GPIO27 показывает **RECORD** и отправляет звук на Mac каждые 154 мс.
При отпускании плата досылает остаток, сервер завершает WAV и запускает распознавание.
Проверенный режим **Hello, world** можно вернуть через `menuconfig` →
**Friday microphone** → выключить **Enable MAX9814 voice capture**.

Используется встроенный драйвер `esp_lcd` и маленький собственный bitmap-шрифт.
LVGL и Arduino не нужны. WebSocket использует компонент Espressif `esp_websocket_client` 1.6.1. Передача идёт полосами по 16 строк,
с ожиданием завершения DMA перед повторным использованием буфера.

## Фоновое распознавание «Пятницы»

В потоковой прошивке после калибровки ESP32 сравнивает поступающий PCM
20 кГц с восемью эталонами. Окно анализа занимает 25 мс, шаг 10 мс.
Значение DTW до 0,19063 включает диагностическое событие. На одно срабатывание
отводится секунда до следующего. После совпадения плата отправляет PCM с конца распознанного слова. Короткая история звука сохраняет начало команды, пока задача детектора заканчивает вычисления.

Для наблюдения открой USB-консоль на 115200 бод. Если плата уже работает,
можно подключиться командой `screen /dev/cu.usbserial-0001 115200`.
Строка `wakeword: PYATNITSA #… score=…` отмечает обнаружение.
Каждые 10 секунд выводятся длительность обработанного аудио `audio` и
затраченное на обработку время `work` в миллисекундах (включает вытеснение
задачи планировщиком). `dropped` считает блоки, которые не поместились в
очередь детектора. При разрыве входной последовательности детектор сбрасывает
историю сравнения и увеличивает `resets`. Поле `heap` показывает свободные байты.

Голосовые эталоны хранятся локально в `firmware/.local/wakeword_model.inc`. Без них работает запись по сенсору. Для голосовой активации подготовь несколько собственных WAV с одним произнесённым словом (моно PCM16, 20 кГц). Из корня проекта в окружении Python с NumPy выполни:

```sh
python3 firmware/scripts/export-wakeword.py --reference first.wav --reference second.wav
cd firmware
./scripts/idf.sh reconfigure build
```

Для вручную обрезанного WAV используй `--trimmed-reference`.

## Подключение

Отключить питание перед перестановкой проводов. Плата питается через USB.
Внешний источник 3,3 В отсоединить от плюсовой шины.

| Дисплей | NodeMCU / ESP32 |
| --- | --- |
| GND | GND |
| VCC | 3V3 |
| SCL | GPIO18 |
| SDA | GPIO23 |
| RES | GPIO16 |
| DC | GPIO17 |
| BLK | 3V3 |

Номера GPIO — обозначения сигналов, **не порядковые номера ножек**.
SCL/SDA на этом дисплее — SPI clock/MOSI, не I²C.
У семиконтактного модуля нет доступного CS: в коде `cs_gpio_num = -1`.
Этот SPI bus выделен дисплею; не подключать к нему другие SPI-устройства без CS дисплея.
Провода должны быть короткими. BLK подключён к питанию, программного управления яркостью нет.

### Микрофон MAX9814

| MAX9814 | NodeMCU / ESP32 |
| --- | --- |
| VDD / VCC | 3V3 |
| GND | Общий GND |
| OUT | GPIO34 (ADC1, канал 6) |
| GAIN | 3V3 — максимальное усиление 40 дБ |
| A/R | Оставить неподключённым |

Подключать при отключённом USB. Дисплей подключён как раньше.
Выход микрофона подключается напрямую: его постоянное смещение убирается программно.
GPIO34 работает только как вход, что подходит для аналогового микрофона.
Не подключать OUT к 3V3 или к выходному GPIO.

### Экран и окончание записи

Плата измеряет фон при запуске. Системные сообщения появляются в нижней строке, в том числе `QUIET PLEASE`, `CHECK INPUT`, `TOUCH CAL`, `NO SERVER` и `RECORD ERROR`. После проверок экран чёрный. При голосовом захвате по центру появляется `LISTENING`. При ручном захвате нижняя строка показывает `RECORD`.

Два последовательных обычных блока выше 1,75 от калиброванного фонового RMS считаются речевой активностью. После полутора секунд тишины плата досылает остаток PCM и завершает WAV. Полторы секунды считаются по отсчётам АЦП, независимо от времени отправки пакетов. Для ручной записи окончанием служит отпускание сенсора.

### Усиление и AGC

`GAIN→VDD` задаёт максимальное усиление 40 дБ, `GAIN→GND` — 50 дБ,
неподключённый GAIN — 60 дБ. Это не выключатель AGC; A/R меняет её времена реакции.
На уровне микросхемы AGC отключается соединением **TH с MICBIAS**, согласно datasheet.
На показанной гребёнке модуля эти контакты не выведены: переделка требует схемы/осмотра
обратной стороны и пайки. Соединять GAIN или A/R вместо них нельзя.
Режима единичного усиления через GAIN у MAX9814 нет; программно изменить его аналоговую
схему ESP32 не может. Для измерений амплитуды удобен тракт с фиксированным усилением.

## Встроенный сенсор касания и сеть

Внешний модуль TTP223 больше не используется. Отключить его, затем при выключенном USB
подключить электрод к **GPIO27 / TOUCH7**:

```text
GPIO27 ── 510 Ом или 1 кОм ── короткий провод ── фольга/металлическая площадка
```

У резистора нет полярности. Площадка не соединяется с GND или 3V3.
Можно касаться зачищенного конца провода; небольшая площадка удобнее.
GPIO27 управляется драйвером `esp_driver_touch_sens` ESP-IDF, цифровые подтяжки не используются.

После подключения Wi-Fi появляется `TOUCH CAL`. Не касаться электрода и не двигать провод:
нужны две секунды стабильных показаний. При заметном изменении ёмкости интервал начинается заново.
Калибровка микрофона идёт параллельно — до `LISTENING` соблюдать тишину и не трогать электрод.

У классического ESP32 показания уменьшаются при касании. Порог нажатия — 80% исходного значения,
отпускания — 90%; дополнительно применяется сглаживание и задержка подтверждения 60/150 мс.
Во время удержания исходное значение заморожено, ограничения на 7 секунд нет.
Медленный дрейф корректируется только без касания. Если существенно изменились провода/площадка,
нажать EN и повторить калибровку без касания.

В USB-логах: `touch: GPIO27: value=... smooth=... base=... press<... release>=... touched=...`.
Это значения ёмкостного сенсора, не логические 0/1 цифрового входа.
Запись по-прежнему запускается удержанием и завершается отпусканием.
В потоковом режиме программный предел записи — 120 секунд; его превышение помечает запись как неполную.

```sh
cd firmware
python3 scripts/configure-network.py
./scripts/idf.sh build
```

Скрипт запрашивает SSID сети Wi-Fi 2,4 ГГц, скрыто запрашивает пароль и URL сервера,
например `ws://mac-host.local:33000/audio`. Mac и ESP32 должны быть в доступной друг другу сети.
Настройки сохраняются только в игнорируемом `.local/network_config.h`, с правами 0600.
Пароль включается в собранный бинарник — не публиковать его вместе с локальными артефактами.
Без настроек сборка возможна, но на экране будет `SETUP WIFI`.
`build` **не прошивает** устройство. При изменении IP Mac повторить настройку и сборку.

Сервер запускается отдельно из соседней папки `server` командой `npm start`.
При потере Wi-Fi/сервера подключение восстанавливается автоматически, но запись
не возобновляется сама: нужно отпустить и снова нажать кнопку.

## Передача звука

По умолчанию прошивка передаёт моно PCM16 на 20 кГц. Непрерывный фильтр 80 Гц
убирает постоянное смещение. Каждые 3072 отсчёта (153,6 мс) уходят одним сообщением WebSocket размером 6144 байта. Очередь вмещает 72 блока АЦП. При завершении голосовой или ручной записи уходят остаток и сообщение `end`.

Для диагностической записи в RAM включите режим явно: `./scripts/idf.sh -DFRIDAY_RAM_CAPTURE_TEST=ON build`. После подключения
и калибровки прошивка выделяет свободную внутреннюю память страницами по 2 КиБ,
с резервом 32 КиБ для работающих задач и сети. Строка `PCM16 RAM` в журнале
показывает доступную продолжительность. Когда память заполнена, сохранённый фрагмент
ждёт отпускания сенсора. Передача начинается после отпускания.

Для сравнения шума включите `-DFRIDAY_WIFI_OFF_CAPTURE=ON` вместе с режимом RAM.
При нажатии появится `PREPARING`: плата остановит WebSocket и Wi-Fi и пропустит
первые 300 мс звука после остановки радио. Говорить можно с появления `RECORD`.
При отпускании плата снова запустит Wi-Fi и передаст сохранённый фрагмент после
соединения с сервером. Короткое касание до начала записи вернёт плату в ожидание.

- В режиме RAM на входе АЦП 20 кГц. После фильтра верхних частот 80 Гц и масштабирования
  ×16 полифазный фильтр ограничивает полосу и пересчитывает поток в 16 кГц.
  Формат записи — моно PCM16 little-endian, 32 000 байт в секунду.
- Чтобы вернуть потоковую сборку из диагностической, задайте `-DFRIDAY_RAM_CAPTURE_TEST=OFF -DFRIDAY_WIFI_OFF_CAPTURE=OFF -DFRIDAY_FIR_PAIR_TEST=OFF -DFRIDAY_FIR_PAIR_CONTROL=OFF`.
- Потеря DMA-данных, переполнение очереди или ошибка передачи прерывают запись.
  Сервер сохраняет `.incomplete.wav` и не распознаёт её. Нет автономной записи без сети.
- Протокол: JSON `start`, бинарные PCM-блоки, JSON `end` с числом отсчётов;
  `abort` обозначает неполную запись. Подробности в `server/AGENTS.md`.

## Установка окружения (macOS / Linux)

Нужны Git и Python 3.9–3.13. На macOS также нужны Xcode Command Line Tools
(`xcode-select --install`, если ещё не установлены).

```sh
cd firmware
./scripts/setup.sh
```

Скрипт скачивает SDK, компилятор ESP32, CMake/Ninja и создаёт Python-окружение
в `firmware/.tools/`. Первичная установка требует интернета и нескольких ГБ места.
Эти файлы исключены из Git; установка не меняет `.zshrc` и не требует глобального ESP-IDF.
На macOS по умолчанию используется `/usr/bin/python3`, чтобы не зависеть от нового
Homebrew Python. Можно явно выбрать другой совместимый Python:

```sh
IDF_BOOTSTRAP_PYTHON=/path/to/python3.11 ./scripts/setup.sh
```

## Сборка

```sh
./scripts/idf.sh build
```

Цель `esp32` уже задана проектом. Результат — `build/friday_firmware.bin`,
загрузчик, таблица разделов и аргументы прошивки в `build/`.
Для первой установки по USB нужны загрузчик, таблица разделов и приложение.

## Обновление по Wi-Fi (OTA)

Первый раз подключи плату по USB, сняв внешнее питание с её пина 5V/VIN.
Из папки `firmware` запусти `./scripts/idf.sh -p /dev/cu.usbserial-0001 flash`.
Полная прошивка создаёт два слота по 1700 КиБ и записывает начальные данные OTA.
Если переносишь старый локальный `sdkconfig`, выбери в `menuconfig` разметку
**Two large size OTA partitions** и включи **Enable app rollback support**.

Для следующих обновлений на том же Маке:

```sh
cd firmware
./scripts/idf.sh ota
```

Дождись сообщения «OTA ready», затем коротко нажми **EN** на ESP32 или
включи её питание. Плата проверяет обновления один раз после подключения к Wi-Fi,
до калибровки микрофона. Если обновление доступно, появится `OTA CHECK`,
образ запишется в запасной слот и ESP32 перезапустится. При пробной загрузке она
проверит запуск дисплея, подключение к Wi-Fi и инициализацию включённых
аудиодрайверов, подтвердит версию и перезапустится для сверки хеша с Маком.
Если при пробном запуске Wi-Fi не подключится за минуту или плата перезагрузится
до подтверждения, загрузчик вернёт предыдущую версию. При обрыве передачи повтори команду и нажми EN.
Для уже установленного образа запись во флеш пропускается.

Команда собирает проект и временно открывает HTTPS на TCP-порту **8443**.
Адрес Мака берётся из локальной настройки WebSocket. Сервер распознавания на 33000
может работать независимо. При запросе macOS разреши входящее соединение из домашней сети.
Успех выводится только после получения от платы хеша запущенного образа.
При отсутствии подтверждения команда завершается с ошибкой через три минуты.

Сертификат, закрытый ключ и токен создаются при первой сборке с помощью OpenSSL.
Сохрани каталог `.local/ota/` при переносе проекта на другой Mac. Он исключён из Git.
Если ключи потеряны, потребуется однократная USB-прошивка с новыми реквизитами.

## Прошивка и логи

Найти порт на macOS:

```sh
ls /dev/cu.*
```

Подставить порт платы вместо примера:

```sh
./scripts/idf.sh -p /dev/cu.usbserial-0001 flash monitor
```

На Linux порт обычно `/dev/ttyUSB0`. Команда `flash` сама собирает изменения.
Выход из монитора: **Ctrl+]**. Скорость логов — 115200 бод.
Если монитор уже открыт, сначала выйти из него через Ctrl+], чтобы освободить порт.
Если загрузчик не подключается: удерживать BOOT, кратко нажать EN,
после начала подключения отпустить BOOT.

## Если есть подсветка, но нет текста

1. Проверить общую землю и четыре сигнальных провода по таблице.
2. Посмотреть логи: должна появиться строка `Voice capture ready`
   (или `Hello, world drawn`, если микрофон отключён в конфигурации).
   Она подтверждает отправку данных, но не ответ дисплея: обратной линии MISO нет.
3. Открыть `./scripts/idf.sh menuconfig` → **Friday display**.
   Здесь меняются GPIO, частота, SPI mode, смещения, инверсия и RGB/BGR.
4. По умолчанию выбран SPI mode **3**, 10 МГц. Для другой ревизии модуля
   попробовать mode **0**; при длинных проводах снизить частоту до 1 МГц.
5. Если картинка смещена/обрезана, попробовать Y offset **80** вместо 0.
   Если перепутаны красный и синий — переключить BGR; если цвета негативные — инверсию.
6. После изменений снова выполнить `flash`.

Wi-Fi использует только диапазон 2,4 ГГц; микрофон подключён к ADC1, совместимому с Wi-Fi.
Работа с АЦП использует периферию I2S0 внутри драйвера ESP32;
это не цифровое I2S-подключение микрофона. Проверять реакцию на настоящий звук нужно
на подключённом и прошитом устройстве.

## Проверка обработки сигнала на компьютере

```sh
./scripts/test.sh
```

Тест проверяет удаление постоянного смещения, RMS известной синусоиды, калибровку
фона с коротким импульсом, нулевой/некорректный вход, голосовое завершение после полутора секунд тишины, перегрузку
и границы отрисовки, а также непрерывность PCM-фильтра между блоками DMA.
Требуется C-компилятор с AddressSanitizer/UBSan.
